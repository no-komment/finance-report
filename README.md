# Расходы

Статическое приложение для личного учета ежемесячных расходов. Работает без backend: HTML/CSS/Vanilla JS, данные хранятся локально в браузере, поддерживаются XLSX/JSON и опциональная синхронизация с GitHub Contents API.

## Что реализовано

- месяцы: создание, изменение дохода/заметки, удаление;
- расходы: добавление, редактирование, удаление;
- поиск, фильтры по категории/типу, сортировка по дню и сумме;
- финансовая сводка с крупным остатком, долей потраченного дохода и сравнением с предыдущим месяцем;
- редактируемые справочники категорий и типов;
- импорт XLSX с preview и режимами `Заменить` / `Объединить`;
- экспорт XLSX с листами месяцев и листом `Виды трат`;
- импорт/экспорт JSON;
- localStorage + seed `data/expenses.json`;
- GitHub Sync с защитой от SHA-конфликтов;
- светлая/темная/автоматическая тема;
- продуктовый desktop-интерфейс с компактным sidebar и отдельной мобильной компоновкой;
- мобильные строки расходов, нижняя навигация, floating action и safe-area для iPhone;
- адаптивность проверяется на контрольных ширинах 1440 / 1024 / 768 / 430 / 390 px;
- клавиатурная навигация и нативные `<dialog>`.

## Интерфейс

Дизайн построен без UI-фреймворков. На desktop используется узкий sidebar с месяцами, одна рабочая поверхность и крупный финансовый баланс вместо сетки одинаковых dashboard-карточек. Категории получают стабильный автоматически вычисляемый цветовой маркер.

На экранах до 980 px sidebar заменяется мобильной навигацией. На телефонах таблица перестраивается в компактные строки, главное действие фиксируется над нижней навигацией, а формы открываются как полноэкранная панель. Учтены `env(safe-area-inset-*)` и размеры порядка 390–430 CSS px, включая iPhone 15 Pro Max.

Темы используют общую систему CSS variables, а анимации отключаются через `prefers-reduced-motion`.

## Исходный Excel

Проект подготовлен по реальному `Отчеты.xlsx`:

- листы `Июль 2026`, `Август 2026`, `Виды трат`;
- таблица расходов находится в B:F;
- в `Июль 2026` справа есть служебные pivot-таблицы H:P — импортер их игнорирует;
- итоговый блок найден по текстовым меткам, а не по номеру строки;
- в `data/expenses.json` уже перенесено 42 расхода за июль и 39 за август;
- доход обоих месяцев — 150000;
- справочники собраны из `Виды трат` и фактических строк расходов.

Импортер не привязан к этим координатам: он ищет подряд заголовки `Дата`, `Вид траты`, `Описание траты`, `Сумма`, `Тип`, а доход — по строке `Заработок (инв. + зп)`.

## Запуск локально

Нельзя надежно открывать `index.html` двойным кликом: браузер блокирует `fetch()` seed JSON для `file://`.

Из корня проекта:

```bash
python -m http.server 8000
```

Затем откройте `http://localhost:8000`.

Сборка, npm и backend не требуются.

## GitHub Pages

1. Создайте GitHub-репозиторий.
2. Добавьте файлы проекта и выполните push.
3. Откройте **Settings → Pages**.
4. В **Build and deployment** выберите **Deploy from a branch**.
5. Выберите `main` и `/ (root)`.
6. Сохраните настройки и откройте выданный GitHub Pages URL.

## Где хранятся данные

### `data/expenses.json`

Seed-версия в репозитории. Используется при первом открытии или после команды «Сбросить к seed JSON».

### localStorage

После первого запуска является основной локальной рабочей копией. Любое CRUD-действие сохраняется автоматически.

Ключ данных: `expenses-app:data:v1`.

Перед массовой заменой/сбросом текущая версия дополнительно сохраняется в `expenses-app:pre-import-backup:v1`.

### JSON backup

`Экспорт JSON` создает полный переносимый backup. `Импорт JSON` валидирует `version`, месяцы и расходы и показывает preview перед применением.

### XLSX

Нужен для совместимости с текущим процессом. Приложение использует SheetJS 0.18.5 через CDN. Если нужна полностью офлайн-версия, скачайте `xlsx.full.min.js` и замените CDN `<script>` в `index.html` локальным файлом.

## XLSX import

Распознаются листы вида `Август 2026`. Русское имя месяца обязательно.

Основная таблица определяется поиском последовательности заголовков:

```text
Дата | Вид траты | Описание траты | Сумма | Тип
```

Строка импортируется только если:

- день — целое число;
- категория и тип заполнены;
- сумма — положительное число.

Поэтому пустые строки, итоговый блок и pivot-таблицы справа не попадают в расходы.

Доход ищется по подписи `Заработок (инв. + зп)`. Первое текстовое значение справа после суммы становится `incomeNote`.

### Merge

При объединении:

- отсутствующие месяцы добавляются целиком;
- для существующего месяца новые расходы добавляются только если нет строки с теми же днем, категорией, описанием, суммой и типом;
- локальный ненулевой доход имеет приоритет;
- пустые локальные доход/заметка дополняются импортируемыми;
- справочники объединяются без дубликатов.

Это консервативная стратегия для личного учета: она не перезаписывает уже отредактированные локальные значения автоматически.

## XLSX export и round-trip

Каждый месяц экспортируется в отдельный лист. Добавляется итоговый блок и `Виды трат`.

Проверяемый формат данных симметричен импортеру, поэтому сценарий `XLSX → сайт → XLSX → сайт` сохраняет расходы, доход и заметку. Уникальные внутренние `id` при импорте XLSX создаются заново — они не являются частью Excel-формата.

SheetJS Community Edition надежно поддерживает ширины колонок и числовой формат. Расширенное Excel-стилизование (полноценные стили ячеек) не является обязательной частью CE, поэтому проект не зависит от него.

## GitHub Sync

GitHub Pages не может сам изменить `data/expenses.json` в репозитории. Для опциональной записи используется GitHub Contents API.

В настройках указываются:

- owner;
- repository;
- branch;
- path, обычно `data/expenses.json`;
- fine-grained Personal Access Token.

### Минимальные права PAT

Создайте fine-grained PAT только для нужного репозитория и выдайте разрешение:

- **Repository permissions → Contents: Read and write**.

Не выдавайте дополнительные права без необходимости.

PAT нельзя безопасно зашить в статический frontend: любой посетитель сможет извлечь его из исходников/DevTools. Поэтому приложение никогда не сохраняет PAT в код, JSON или localStorage. Введенный токен помещается только в `sessionStorage` и исчезает после завершения браузерной сессии.

Перед PUT приложение читает текущий файл и его SHA. Если SHA изменился, интерфейс предлагает:

- загрузить удаленную версию;
- объединить удаленную и локальную версии;
- отменить действие.

После merge нужно повторно нажать «Сохранить в GitHub».

## JSON схема

```json
{
  "version": 1,
  "settings": { "currency": "RUB", "locale": "ru-RU" },
  "categories": [],
  "types": [],
  "months": []
}
```

Вычисляемые итоги не хранятся — они всегда пересчитываются из расходов. Это исключает рассинхронизацию. Функция `migrateData()` является точкой для будущих миграций `v1 → v2`.

## Безопасность

Пользовательские значения выводятся через DOM API и `textContent`, а не через пользовательский `innerHTML`. JSON и XLSX валидируются. При XLSX-экспорте описание, начинающееся с `=`, `+`, `-` или `@`, получает безопасный префикс для снижения риска formula injection.

Секретов и токенов в проекте нет.
