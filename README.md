# Расходы

Персональное PWA-приложение для учёта расходов, доходов и капитала. Интерфейс работает на Vanilla JS, данные сохраняются локально для офлайн-работы и автоматически синхронизируются с Cloudflare D1 через защищённый Pages Functions API.

Проект рассчитан прежде всего на личное использование: его можно установить на iPhone/Android/desktop как PWA, работать без сети, импортировать и экспортировать XLSX/JSON, смотреть локальную аналитику и защищать доступ паролем и биометрией устройства.

## Возможности

- **Расходы:** добавление, редактирование и удаление операций, категории, типы, поиск, сортировка и фильтры.
- **Доходы:** несколько источников дохода внутри месяца, общий доход и заметка.
- **Капитал:** отдельный список счетов, накоплений и мест хранения с владельцем, суммой и валютой.
- **Месяцы:** создание, изменение и удаление периодов.
- **Аналитика:** выбор месяца или диапазона дат, доходы vs расходы, баланс, сравнение с предыдущим периодом, структура расходов, источники дохода, крупнейшие операции и автоматические наблюдения.
- **XLSX:** импорт с preview и режимами «Объединить» / «Заменить», экспорт всех месяцев в Excel.
- **JSON:** полный переносимый backup и восстановление состояния приложения.
- **PWA:** установка на домашний экран, собственная иконка и офлайн app shell.
- **Темы:** светлая, тёмная и автоматическая.
- **Приватный режим:** экран-приманка с шаблонными данными и кнопкой-глазом для показа настоящих данных.

## Архитектура

```text
Браузер / установленная PWA
        │
        ├── localStorage
        │   └── мгновенная рабочая копия + офлайн
        │
        ├── Service Worker
        │   └── кэш интерфейса приложения
        │
        └── /api/data
              │
              ▼
       Cloudflare Pages Functions
              │
              ▼
          Cloudflare D1
```

GitHub хранит **код проекта**, но не рабочую финансовую базу. Публикация выполняется через Cloudflare Pages.

## Где находятся данные

### localStorage

Основная локальная рабочая копия находится под ключом:

```text
expenses-app:data:v1
```

Любое изменение сначала сохраняется локально. Благодаря этому приложение продолжает работать при отсутствии интернета.

### Cloudflare D1

Удалённая актуальная копия хранится в D1 в таблице `app_data`.

Изменения автоматически отправляются в D1 примерно через секунду после редактирования. Серия быстрых правок объединяется в одну синхронизацию.

При восстановлении сети приложение повторяет незавершённую синхронизацию. При открытии приложения облачная версия также проверяется.

API D1 намеренно исключён из Service Worker Cache.

### JSON backup

Экспорт JSON создаёт полную переносимую резервную копию. Перед крупным импортом рекомендуется сохранять JSON отдельно.

## Офлайн-режим

После хотя бы одного успешного онлайн-запуска PWA может работать без интернета:

1. интерфейс открывается из Service Worker Cache;
2. финансовые данные читаются из localStorage;
3. новые изменения сохраняются локально;
4. после появления сети они автоматически уходят в D1.

Первый запуск на новом устройстве требует сети.

## Авторизация и защита

В проекте два независимых слоя защиты.

### Серверная авторизация

Cloudflare Pages Function `_middleware.js` защищает приложение паролем.

Пароль хранится в Cloudflare как Secret:

```text
APP_PASSWORD
```

Подпись сессии использует отдельный Secret:

```text
SESSION_SECRET
```

После успешного входа сервер устанавливает защищённую `HttpOnly; Secure; SameSite=Strict` cookie. Срок сессии по умолчанию — около 30 дней.

### Face ID / Windows Hello

Локальная блокировка использует WebAuthn и платформенный аутентификатор:

- iPhone/iPad — Face ID или Touch ID;
- Windows — Windows Hello;
- другие устройства — доступный системный WebAuthn-аутентификатор.

Приложение не получает изображение лица или отпечаток пальца — только криптографическое подтверждение от ОС.

Короткое переключение между приложениями имеет grace period. Повторная биометрия требуется после более долгого отсутствия или нового запуска в соответствии с логикой `app-lock.js`.

### Экран-приманка

При защищённом запуске приложение может показывать шаблонные финансовые данные. Настоящие значения открываются кнопкой-глазом.

Шаблон существует только на уровне интерфейса и не записывается вместо реальных данных в localStorage или D1.

## Аналитика

Аналитика выполняется **полностью локально**, без отправки финансовых данных стороннему AI/API.

Поддерживаются:

- конкретный месяц;
- произвольный диапазон дат;
- последние 30 / 90 дней;
- период с начала года;
- общий доход;
- общий расход;
- баланс;
- доля расходов от дохода;
- сравнение с предыдущим периодом такой же длины;
- график доходов и расходов;
- динамика расходов;
- категории расходов;
- типы расходов;
- источники дохода;
- крупнейшие операции;
- автоматические текстовые наблюдения.

Для неполного диапазона внутри месяца доход оценивается пропорционально выбранным дням, потому что доход пока хранится помесячно.

Код аналитики заранее понимает необязательное поле `incomeSources[].category`, поэтому в будущем можно добавить категории доходов без полной переделки аналитического модуля.

## Импорт XLSX

Импортёр распознаёт листы с русскими названиями месяцев, например:

```text
Август 2026
```

Таблица расходов определяется по последовательности заголовков:

```text
Дата | Вид траты | Описание траты | Сумма | Тип
```

В импорт попадают только корректные строки: день, категория, тип и положительная сумма.

Режим **«Объединить»** сохраняет существующие данные и добавляет отсутствующие операции. Дубликат определяется по сочетанию:

```text
день + категория + описание + сумма + тип
```

Режим **«Заменить»** следует использовать только когда импортируемый файл уже является полной актуальной копией.

## Экспорт XLSX

Каждый месяц экспортируется на отдельный лист. Экспорт предназначен и для обычного просмотра в Excel, и для последующего обратного импорта в приложение.

## Cloudflare

### Pages

Frontend публикуется из GitHub-репозитория через Cloudflare Pages.

Проект не требует npm-сборки или frontend-фреймворка.

### D1 binding

Pages Functions ожидают D1 binding:

```text
DB
```

### Переменные и Secrets

Используемые значения:

| Имя | Тип | Назначение |
| --- | --- | --- |
| `DB` | D1 binding | база `finance-report-db` |
| `APP_PASSWORD` | Secret | пароль приложения |
| `SESSION_SECRET` | Secret | подпись серверной сессии |
| `D1_API_ENABLED` | Text | `1` включает API синхронизации |
| `APP_SESSION_DAYS` | Text, опционально | срок серверной сессии |

Значения Secrets не должны попадать в GitHub.

## Основные модули

`app.js` — интерфейс и пользовательские действия.

`storage.js` — localStorage, начальная загрузка и D1 autosync.

`expenses.js` — операции с данными расходов и месяцев.

`xlsx.js` — импорт и экспорт Excel.

`github-sync.js` — совместимый слой облачной синхронизации; фактически работает с `/api/data` и Cloudflare D1.

`app-lock.js` — WebAuthn, биометрическая блокировка и экран-приманка.

`analytics.js` — локальная финансовая аналитика и графики.

`about.js` — интерактивное окно «О приложении» и live-статус PWA.

`functions/_middleware.js` — серверная авторизация.

`functions/api/data.js` — чтение и запись D1 с проверкой версии.

`sw.js` — офлайн app shell и стратегия network-first.

## Локальный запуск

Из корня проекта:

```bash
python -m http.server 8000
```

Затем:

```text
http://localhost:8000
```

Frontend откроется локально, но Cloudflare Pages Functions и D1 при таком запуске недоступны. Для полноценной локальной эмуляции Cloudflare потребуется Wrangler.

## Обновление проекта

Обычный workflow:

```bash
git add .
git commit -m "Описание изменений"
git pull --rebase origin main
git push
```

После `git push` Cloudflare Pages автоматически создаёт новый production deployment.

Для финансового проекта перед крупными изменениями рекомендуется дополнительно делать **Экспорт JSON** из самого приложения.

## Проверка после обновлений

Минимальный smoke-test:

1. открыть приложение и пройти авторизацию;
2. проверить Face ID / Windows Hello;
3. открыть настоящие данные кнопкой-глазом;
4. создать тестовый расход и убедиться, что он появился после перезагрузки;
5. проверить D1 autosync;
6. проверить офлайн-запуск;
7. открыть аналитику;
8. проверить импорт/экспорт XLSX;
9. открыть «О приложении» и проверить статусы.

## Принципы проекта

- финансовые данные не хранятся в репозитории;
- Secrets не находятся во frontend;
- работа с данными возможна офлайн;
- облако является синхронизируемой копией, а не единственной точкой отказа;
- аналитика работает локально;
- проект остаётся максимально простым: HTML, CSS и Vanilla JS без лишнего frontend-стека.
